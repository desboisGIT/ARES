# Phase 2 handheld capture and bench procedure

No camera, handheld recordings, or onboard ARM computer was available during software implementation. These instructions prepare human measurements; they do not claim that Phase 2 hardware gates passed. Current replay odometry is a depth/gyro ICP baseline, not full stereo visual-inertial odometry. Stage A acquisition and the measurements below are human tasks; this software does not order hardware or control flight.

Use an already available compatible RealSense rig with depth, both infrared streams, accelerometer and gyroscope. Install the vendor-supported librealsense Python binding separately; the normal ARES CLI does not import it. Check the requested resolutions/rates in RealSense Viewer first. The recorder requests 63 Hz accelerometer and 200 Hz gyroscope; incompatible configurations fail rather than silently substitute streams.

```bash
python3 scripts/capture_realsense.py recordings/place01-on --recording-id place01-on --profile-id YOUR_PROFILE_ID --duration 60 --max-frames 2000 --emitter on
```

Use a fresh output directory. Capture ends at the duration or depth-frame cap, whichever comes first. Defaults allow a one-minute route: 60 seconds, 2,000 depth frames at 640 × 480 and 30 fps. Maximums are 600 seconds and 20,000 frames; choose a cap large enough for the planned route.

Depth is spooled directly to a preallocated uint16 memory-mapped file, then converted to float32 metres in chunks of at most eight frames. The normalized array is also disk-backed while being saved; the recorder does not hold an entire image sequence in RAM. Preflight requires free disk for the full configured capacity: raw depth (2 bytes/pixel), normalized depth (4), a conservative uncompressed NPZ allowance (4), plus `--bag-reserve-gib` (default 4 GiB, minimum 1). At the defaults, the depth allowances total about 5.72 GiB plus the native-bag reserve. This is an estimate, not a guarantee: the native bag also contains stereo IR, depth, IMU and metadata. Increase the reserve for longer recordings and monitor disk space; do not rely on sparse-file allocation as available physical capacity.

After a successful normalized save, only the recorder's `.depth_raw.u16` and `.depth_normalized.npy` temporary files are deleted. On capture or conversion failure, keep the bag, failure report and any spool files for recovery; the directory is incomplete and must not be treated as a valid recording. Each motion stream is capped at 300,000 samples. Native SDK buffering or USB losses remain possible: the report counts observed per-stream counter gaps, not losses before the first or after the last observed frame.

Each capture keeps `capture.bag`, the SDK-native depth, stereo infrared and asynchronous motion recording. Preserve it unchanged for stereo tracking development; normalized `frames.npz` does not include stereo imagery. `capture_report.json` records frame timestamps, per-frame emitter metadata, timestamp domain, motion rotations, depth units and observed frame-counter gaps. Null emitter metadata means unknown, never projector-off. `--emitter alternate` requires both the advertised option and per-frame emitter metadata; support must be checked on the actual camera/firmware. Raw metadata identifies patternless infrared frames (`emitter_mode == 0`); do not infer alternation from even/odd frame numbers. Compare `--emitter on` and `--emitter off` on the same route; alternation is a separate experiment.

Normalized metadata follows `ares.sensor_recording.v1`. The depth array is float32 metres with invalid zero-depth pixels replaced by NaN; intrinsics come from the selected depth stream. Depth pixels remain in the camera optical projection. IMU vectors rotate with the SDK factory motion-to-depth extrinsics, followed by optical-to-body basis `[[0,0,1],[-1,0,0],[0,-1,0]]`: body x forward, y left, z up. This assumes the handheld body is aligned with the depth camera; it is not an airframe mount calibration. Translation lever-arm corrections are not applied.

All sensors must support enabled SDK global-time conversion. The SDK can initially report hardware-clock timestamps while its conversion is warming up. The recorder discards every normalized sample until all configured stream keys (including both infrared streams) have reported global time; the frame completing readiness is discarded too. Startup frames remain in the native bag. The report records `clock_ready`, discard counts per stream, and observed domains. Warmup consumes the configured capture duration; it never extends the time cap. If a stream never becomes ready before capture ends, normalization fails. After readiness, every accepted frame must remain in the global-time domain; a fallback domain or nonmonotonic stream timestamp/counter rejects normalization, retaining the raw bag/report. One common origin is subtracted after capture; no independent per-stream zeroing or host-arrival timestamp substitution occurs. Accelerometer and gyroscope samples arrive asynchronously. The normalized shared IMU timeline is their union within their common coverage, with each vector linearly interpolated, without extrapolation. Native rates and original samples remain in the bag. The normalized IMU interval can cover less than the depth interval; downstream replay must explicitly handle those boundaries.

For at least three distinct real places, with permission to record locally:

1. Record the place identifier, layout sketch, lighting, camera settings, rig height, profile identifier and software/firmware versions. Avoid identifiable people. Keep recordings local; no upload is needed.
2. Hold the rig at intended flight height. Include a stationary beginning/end, slow translations, turns, corridor/doorway passages and a closed route returning to the marked start pose. Measure start/end position and orientation references to report loop error independently of the estimator.
3. Repeat the same route with infrared emitter on/off. Inspect raw stereo images and metadata, depth validity, timestamp monotonicity, stream counter gaps, and IMU coverage before using the recording.
4. Capture stationary reference planes at several measured distances with a registered ruler/plane reference and saved pixel masks. Include ordinary matte, black, shiny and glass surfaces; record oblique angles and boundary masks separately. Preserve reference geometry, material labels and units alongside the logs. Measure depth residual distribution, valid fraction and edge bias by distance/material; fit noise only to training recordings, then report held-out residuals.
5. Replay odometry/mapping, save estimated trajectory/map, compare the independently measured loop closure, and inspect all three maps. Import a measured room with documented coordinate registration; compare simulated and observed depth using the registered reference masks. Neither successful synthetic replay nor an unregistered visual comparison satisfies the real-data gates.

For bench rates, `ares.rate_probe.measure_callable` measures synchronous completed work with warmup, median/p90/p99 duration and total-work throughput. When `target_hz` is supplied, `meets_target` requires p99 duration to fit the period. Synchronize GPU work inside the measured callable. Include odometry, mapping and a dummy policy, and also measure combined replay/end-to-end latency separately; component timing alone does not establish schedulability. Record CPU/GPU, machine model, OS, profile and recording IDs, frame dimensions, warmup/iteration count, thread settings, power mode and temperature. Desktop RTX 5070 Ti measurements describe that host only. Run unchanged software on the actual onboard computer before claiming its rate gate or buying an airframe.
