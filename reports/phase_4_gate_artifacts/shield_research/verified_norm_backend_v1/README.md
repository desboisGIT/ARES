# Explicit verified-norm CPU numerical backend

This research-only backend removes the opaque norm/sqrt primitive obligation from the selected CPU plant path. It retains the SAME REAL full13D rigid-body, geometric quaternion, nominal body-rate controller, motor-lag and discrete RK4 equations. It does not alter any of the 51 frozen ARES package sources, the NN runtime or the historical backend. It emits no flight certificate.

`verified_sqrt.sqrt_word(x)` accepts a represented nonnegative finite binary32 word. It uses `math.sqrt` only to guess nearby output bit patterns. Each candidate's adjacent binary32 values define exact rational rounding midpoints L and U. A positive candidate is accepted only if `L² < x < U²`, with equality accepted precisely when the candidate's significand is even; a negative lower midpoint for zero is handled separately. Thus squaring monotonicity on the nonnegative axis proves round-to-nearest-even of the mathematical square root. No approximation guarantee for Python/libm sqrt is needed. A poor guess causes an exact rejection, never acceptance of an incorrect word. Negative zero is preserved. Rational-extension tests exercise midpoint ties and subnormal output boundaries even when such a tie is not generated by a binary32 input.

`explicit_norm(v,n,audit)` computes exactly n eager binary32 products and n-1 left-associated binary32 additions, n=3 or4. Each represented sum is passed to the verified scalar sqrt and returned as an exact binary32 output word. The three-component norm is used for the original RateController gyro-clamp denominator. The four-component norm is used for original quaternion normalization after `rk4(self.dynamics,...)` and during reset. Original tensor matvec, cross products, clamp, torque/thrust ordering, quaternion rotations/multiplications, RK4 ordering and divisions remain unchanged. The norm implementation performs no Torch norm or library sqrt call. Every generated sqrt point is verified at runtime; witness counts and a digest of input/output words are returned. No sample-derived table establishes primitive correctness.

`ConditionalVerifiedNormCPUBackend` is a NEW guarded variant. It reuses the historical worker's state/domain/queue/parameter guards but instantiates only the new explicit-norm adapter, including initialization and reset. The old wrapper and old artifacts remain unchanged. Construction checks frozen51 hashes and the dedicated-worker CPU guard; it uses one thread, highest Float32 matmul, oneDNN disabled, no autocast/compile, and per-step RNE/DAZ/FTZ checks. It rejects changed model/controller paths. If a point witness or program operation fails during a step, it latches blocked and reports state may already have advanced; no further step is admitted before a valid reset. The domain remains the previously published full terminal guard domain, including |world_position_i|<=16, the projective q box and8u norm shell, physical parameter set, SI queue words, rates, motor and represented battery[.95,1].

## Uniform budget compatibility

The prior roundoff engine assumed gamma6 for a three-square sum and gamma8 for four squares, with4n*2^-126 absolute underflow allowance. The new DAG has only2n-1 rounded product/add operations, so its standard forward bound fits the existing gamma_(2n) and absolute allowance. Each runtime sqrt returns exact RN-even of its represented argument, which implies the prior0.5ULP primitive error contract. Therefore the existing analytical21D per-H error vector, positive-quaternion projective alignment,8u normalization shell and intermediate-position arithmetic padding remain valid. `budget_compatibility.json` records the exact operation-count inequalities and SHA-bound dependencies. This compatibility argument is uniform; the finite comparison does not define or fit the bounds.

Remaining assumptions are ordinary full-precision IEEE binary32 basic arithmetic/conversions under the guarded RNE/gradual-underflow settings, matching frozen source and explicit eager DAG, the already covered short-sum/three-product matrix arithmetic route with oneDNN disabled, and no concurrent mode/code mutation. The normative sqrt rounding property is now proved per point rather than assumed of installed Torch/libm. Verified decay already removes the native exp requirement, and the separate verified public point-law avoids a native atan requirement. A physical hard state/map service, RPI admission/coupling and physical continuous-time model guarantees remain separate. Whole-program/platform and flight-certificate flags are not asserted here.
